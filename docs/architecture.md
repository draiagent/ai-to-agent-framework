# 核心架構與名詞

本版只保留 aOS、Functions、Skills 三層分工。aOS 是本方法論的協調角色名稱，不是宣稱已提供可部署作業系統。

## aOS｜思考與調度

接收人的目標與任務上下文，整合可用記憶，選擇模型與工作方法，協調執行。ChatGPT、Gemini、Claude 在本專案以平台／模型家族的易讀名稱呈現；實際使用需記錄具體平台、模型、版本與可用工具，不將品牌名称當成特定模型版本。調度可以由人完成，也可由已實作的 Agent 完成。

## Functions｜執行與防護

提供檔案讀取、資料處理、剪輯輸出等操作，以及必要檢查與權限控制。Tools 是具體操作能力；MCP 是可選連接方式，不等於工具本身，也不是每個任務都必需。可用功能以實際環境為準。

## Skills｜可重用工作方法

整理業務步驟、判斷原則、輸入輸出與品質要求。Skill 可指導 Agent 使用 Functions；單純寫出 Skill 並不會自動取得工具權限或執行能力。

## 橫跨三層的藍圖

VAD：視覺化任務設計，用圖呈現問題、素材、目標與關係。
VAC：任務規格，明確寫出交付物、限制、驗收條件與必要決策邊界。

兩者相互補充。重要規格保留文字，不能僅靠圖中小字或圖像推測。

## 協作與責任

人決定目標與重要取捨；aOS 理解任務並選用 Skills；Functions 執行具體操作；結果依 VAC 檢查。Memory 收在 aOS；檢查與權限是機制；Golden Case 是測試案例。以上均不新增第四層。

本版不將框架改名為多代理框架或證據驅動框架，也不要求三模型平行競賽。選擇能力應考慮完成任務所需的品質、時間、工具、人工作業與重做成本；目前沒有實測數值。
